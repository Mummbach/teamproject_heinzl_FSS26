Cohort Selection
Inclusion Criteria
  • Adult ICU patients (age ≥ 18)
  • MIMIC-IV v3.1 — Beth Israel Deaconess MC
  • ICU stay length of stay ≥ 2 days
  • First ICU stay per patient only (prevents data leakage)
Exclusion Criteria
  • Patients who died within 48 h of admission (label noise prevention)
  • ICU stays > 90 days (extreme outlier / LTACH transfers)
  • Pediatric patients (age < 18)
  • Repeat ICU stays (only index admission used)

Observation Window

48h
post-admission observation window

All time-series and medication features are extracted within the first 48 hours to enable early prediction and prevent outcome leakage.

ℹ︎  Minimum LOS filter of 2 days ensures every patient has at least 48h of available data

Key Anti-Leakage Measures

  • Imputer medians fitted on training data only
  • StandardScaler fitted on training data only
  • Medications restricted to first 48h window
  • First ICU stay only per patient
  • No future information (intime / outtime excluded from features)
  • Fixed random seed 42 for full reproducibility

Feature Engineering — ICD Diagnoses & ATC Medications

Code Aggregation
ICD-9 / ICD-10 Diagnoses → 18 Binary Categories

Thousands of raw ICD codes are mapped to 18 clinically meaningful disease categories using a rule-based prefix mapping. Each category is a binary flag (1 = any diagnosis in that category present).

NDC Drug Codes → 14 ATC Level-1 Classes (First 48h)

Prescriptions are mapped via NDC → RxCUI → ATC Level-1 using the RXCUI2atc4 crosswalk file. Only medications prescribed within the first 48h of ICU admission are included.

Design Rationale
  • GRU branch processes the 48h vital sign sequences to capture temporal dynamics (trends, deterioration)
  • Static MLP processes demographics, diagnoses, medications
  • Fusion captures interaction between temporal and static factors
  • Class weighting addresses 3.2:1 imbalance without oversampling
  • Early stopping via validation F1 as primary metric

Interpretation

Strengths

  • AUROC 0.84 — excellent discrimination between short and long stays; strong baseline for a first model
  • Recall 0.79 — the model catches ~79% of all true long-stay patients; critical for clinical screening
  • Val and test performance are consistent — no sign of overfitting despite 30 epochs
  • Training loss monotonically decreases from 0.87 → 0.65

Limitations / Areas to Improve

  • Precision 0.49 — about half of positive predictions are false alarms; expected given imbalance (3.2:1)
  • No textual or imaging data yet
  • Single model architecture — no ensembling or comparison yet
  • Calibration not yet evaluated

Open Questions for Discussion (1–5)

Discussion
1
Anchor Age Calculation We used the anchor_age column directly as the patient's age. You calculated actual age using anchor_year as reference year. Is our approach acceptable, or does the age-from-anchor-year method yield meaningfully different values?
2
Outlier Removal — Long-Stay Patients (90-day threshold) We removed stays >90 days. Would a different cutoff (e.g., 150 days) be more appropriate — especially if the goal is to predict clinically significant long-stay patients? What is the trade-off?
3
Exclusion of Early Deaths (48h threshold) We excluded patients who died within 48h of admission to avoid label noise. Would a different threshold (e.g., 5 days) be more appropriate?
4
Prediction Time Point We want to define together at what point in time the prediction should be made. When are medication and diagnosis data typically recorded — day 1, day 3, or later? Should we restrict our feature set to data available up to a specific day?
5
Transfers Between Facilities Transferred patients appear as short stays from a single-hospital view, but may have much longer total system stays. Should we account for this in the label or as a feature?

Open Questions for Discussion (6–11)

Discussion
6
Planned Admissions How should we treat patients with planned admissions who are told in advance about a specific stay length (e.g., 4 days)? Should these be excluded or handled separately?
7
Time-Related Features (intime / outtime) — Data Leakage Risk Features like intime and outtime could cause data leakage. Should we exclude them entirely, or could they be used for time-based splitting only?
8
Aggregating Multiple Stays per Patient We currently use only the first ICU stay. A patient might stay 5 days initially, then be readmitted 4 more times for a total of 50 days. Would aggregating all stays give a more realistic picture?
9
Classification Boundary — Exactly 7 Days In our binary classification, does a stay of exactly 7.0 days count as "under 7 days" (negative) or "over 7 days" (positive)? Currently: >7 days = positive, so exactly 7 = negative.
10
Stratified Splitting & Subgroup Distribution We stratified on the binary label but did not verify balanced subgroup distribution (e.g., circulatory disease patients) across splits. Should we check this explicitly?
11
Repository Access The repository is currently private (MIMIC-IV data should not be public). Would you like access? Please share your GitHub handle and we will add you.

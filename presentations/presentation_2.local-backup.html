How PRD-Net v2 Predicts: Contrastive Prototype Comparison

Approach

Task

Binary classification — will this ICU stay exceed 7 days?

Input: clinical data from the first 24–48h of an ICU stay. Output: probability of prolonged stay + a named, per-feature reason.

Core Idea

Don't classify in the abstract — compare against two concrete reference patients.

Build a "typical long-stay patient" and a "typical short-stay patient" from real peers, then measure the new patient against both, feature by feature.

Prediction Pipeline (Conceptual)
1. Find peersembedding distance (reused from v1) + hard clinical filter
2. Build 2 prototypesavg. long-stay peer vs. avg. short-stay peer, in raw feature space
3. Signed deltasΔ = patient − prototype, kept per feature (never collapsed)
4. Weighted sumlinear model combines all Δs into one prediction

Reused From v1 (Existing GRU Track)

  • Patient embeddings from the already-trained GRU model (64-dim latent fusion vector)
  • Peer retrieval — hard clinical filter + K-nearest-neighbor search in that embedding space — taken as-is, no retraining
  • This answers "who counts as similar" — pipeline step 1 above

New in v2 — What We Do With Those Peers

  • Instead of comparing embeddings, average the peers' real clinical feature values into two prototypes
  • Signed per-feature differences, never collapsed to one distance number
  • Linear model ⇒ contribution of each feature is exact (mathematically identical to SHAP)
logit = Σᵢ wᵢ · (patientᵢ − prototypeᵢ) + b
Because the model is linear, each term wᵢ·Δᵢ IS the exact contribution — not an approximation.

Architecture — Input, Processing, Output

F = 77 Features

Input — 77 features / patient

12 vitals × 5 stats (mean/last/min/max/slope) = 60, + age = 61, + 16 CXR-derived flags (pneumonia, ventilator, ...) = 77.

Heart rateSBP / DBP Resp. rateSpO₂ GCS (eye/verbal/motor)Glucose

Processing

  • Hard filter: same ICD chapter, ICU type, admission type
  • + age tolerance, then K-nearest peers by embedding distance
  • Δpos = patient − long-stay prototype
  • Δneg = patient − short-stay prototype
  • Model input = concat(Δpos, Δneg) → dim 154

Output

p(Long Stay) — calibrated probability, plus the exact per-feature contribution wᵢ·Δᵢ for every input dimension (no post-hoc approximation needed).

What AUROC ≈ 0.76–0.78 Implies

Probability a randomly chosen long-stay patient is ranked higher-risk than a randomly chosen short-stay patient — ≈77% of the time vs. 50% for a coin flip. Solid, clearly-above-chance discrimination, though not "excellent" (>0.90) — real overlap remains between the two groups.

What AUPRC ≈ 0.47–0.51 Implies

The imbalance-sensitive metric: at 23.7% prevalence, a no-skill ranking scores only 0.237 — so this is roughly a 2× lift over chance. Real signal, but still well below 1.0: even top-ranked alarms carry a meaningful false-positive share (matches precision ≈0.45–0.47).

CXR effect: the with-CXR model scores slightly lower across all six metrics than no-CXR — consistent with only 2.3% of patients (702/30,615) having a usable report, which dilutes rather than lifts the aggregate numbers. Its payoff is per-patient explanation richness for that subset, not these scores.

Next Steps

Roadmap

1 · Local vs. Global Model

Put v1 (global, whole-patient embedding) and v2 (local, per-feature) side by side in the dashboard.

  • Currently only an aggregate F1 comparison (distance view vs. difference view)
  • Goal: per-patient toggle so a clinician can judge, case by case, which explanation is more useful

2 · Predicted LOS via Regression

Go beyond the binary >7-day threshold to an actual estimated day count.

  • Current model only classifies Long/Short Stay — no day-count prediction exists
  • Needs a regression head or a separate model trained on continuous LOS
  • More directly actionable for clinical planning than a binary flag

3 · Further Metric Tuning

Push AUPRC/AUROC higher; fix known overconfidence at low peer support.

  • Most-confident predictions are wrong far more often than average (thin peer groups → noisy prototypes)
  • Calibrate / shrink probability when peer support is low
  • Revisit CXR coverage — wider report-matching window, or accept as a minority-case signal

Interpretability is already there — the next phase is closing the remaining performance gap and turning the explanation into a decision-support number a clinician can plan around.
